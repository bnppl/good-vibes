# Engineer visualization implementation contract

Repository: `/workspace/scratch/c46edf781200/good-vibes`. Read `CLAUDE.md`. Each implementer owns only its named JS, CSS and route page; do not edit shared files, other views, research caches or existing maps. Do not commit or push; the root agent integrates and publishes. No sub-delegation needed.

## Module

Register `window.EngineerVisuals['SLUG'] = function(ctx) { ... }`, initializing `window.EngineerVisuals = window.EngineerVisuals || {}`. No external dependencies or network calls. Shared scripts load your module before invoking it. Use ordinary browser APIs and vanilla JavaScript. No ChatGPT-only runtime or inline visualization fragment.

`ctx` supplies:
- `root`: empty DOM container for your visual, id `visual-root`.
- `profiles`: all 20 current cached profiles. Shape: `{id,name,aliases,tagline,summary,focus,focusNote,checked,cutoff,tools,dimensions}`. `dimensions` is the original D01–D12 array: each item has `id,title,position,evidence,claim,detail,source,checked,qualification`.
- `baseurl`: site base path, e.g. `/good-vibes`.
- `el(tag, className, text)`: create an element; optional class/text. Use textContent for source text, never untrusted innerHTML.
- `link(label, href)`: ordinary anchor, external URLs get target=_blank and rel=noopener.
- `profileUrl(profile, claim)`: native profile URL; optional claim such as `C04` adds #c04.
- `dimension(profile, id)`: matching dimension or null.
- `evidenceLinks(profile, ids)`: compact DOM group linking named dimensions to native claim anchors and primary sources, preserving dates/evidence in the accessible text.
- `icons()`: initialize the local Lucide subset (available icons: git-branch, shield-check, book-open, code-2, terminal, activity, flask-conical, list-checks). Icons must have text labels; unknown names are not supported.

Use own CSS for real charts, diagrams and useful layout; avoid decorative dashboards. No fixed outer width/height or page horizontal overflow. At 320px reflow/stack while retaining readable labels and 44px effective controls. Prefer responsive SVG actual measured viewBox; don't scale unreadable text.

## Evidence

Use only cached `engineers/PERSON/` research, sources and workflow examples. Read relevant profiles before attributing methods. Distinguish self-report, recommendation, inspected artifact, historical guidance, our synthesis/adaptation, and unknown. Never invent scores, effectiveness rankings, timings, costs or risk ratings. Checked date is not source/practice date. AI-system evaluation is distinct from software unit TDD. Don't infer non-use from missing evidence. Preserve exact dates and authorship. Publication of a framework is not current daily adoption. Tool relationships distinguish created, used, endorsed and assessed.

All 20 must be accessible in each view (selector or meaningful overview). Focus on a clear dominant visualization with useful interactions. Where workflows/project fits are proposed applications, show an explicit visible 'Interpretive adaptation' label and link the attributed evidence. Do not fake observation of engineers running the shared example. Common bug example is reward/idempotency: empty=0; A=10; replay A=10; restart with durable data and read before replay=10; replay after restart=10; distinct B=20. AI-product variants must stay clearly distinct from applying AI evaluation to a deterministic bug.

Run `node --check` for your JS. Report files, evidence basis, interactions, limitations and any concerns. Root will run browser checks and integrate.
